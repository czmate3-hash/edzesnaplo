# Edzésnapló – final QA audit

Date: 2026-08-28

## Implemented hardening

- Previous-day goal finalization is performed at startup and not as a failure of the current day.
- Goal-rise events are protected by a unique `(user_id, exercise_id, day)` constraint.
- Goal progression now uses the first configured number of recorded workout values from the successful streak, not daily aggregate totals.
- Count goals round to whole numbers; time goals round to 10 seconds.
- Calendar supports previous/next month navigation.
- Statistics range requests send real `from`/`to` dates for 7-day and 30-day views.
- Goal ring is calculated from actual daily progress.
- Rest-day status does not break streaks and workouts remain allowed.
- Challenge state is refreshed by database triggers after workout/participant changes.
- Race challenges use cumulative participant totals and the first participant to cross the goal becomes the winner.
- Challenge records now support completed/expired metadata.
- PIN login/recovery has server-side rate limiting and session invalidation on recovery.
- Security-definer RPC functions are no longer executable by `anon`/`authenticated` roles; required internal auth functions remain executable by `service_role`.
- PWA cache bumped to v7.

## Remaining verification boundary

A real Android/iOS browser cannot be physically driven by this connector, so the following are not claimed as device-E2E PASS: physical PWA installation, Safari-specific behavior, offline/reconnect behavior, and touch interaction. The backend/database scenarios are tested; the repository's static QA workflow remains the source of truth for source-level checks.
